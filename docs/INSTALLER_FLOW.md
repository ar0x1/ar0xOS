## 2. ⚠️ MANDATORY pre-install disk check (RISK-004)

**Do this on the live system BEFORE launching the installer. It is not
automated and must not be.**

```bash
lsblk -o NAME,SIZE,MODEL,TRAN
#   NAME        SIZE MODEL            TRAN
#   sda         512G Samsung SSD      sata     <-- host disk, DO NOT TOUCH
#   vda          40G QEMU HARDDISK    virtio   <-- TARGET
```

Write down the **exact** target device name (e.g. `vda`) and type it into the
partition page. If you see **more than one disk**, stop and re-read the output.
`config/calamares/modules/partition.conf` sets
`initialPartitioningChoice: none`, so Calamares never pre-selects a device, and
`settings.conf` sets `prompt-install: true` so you get one last "Are you sure?"
before the exec phase. The `summary` page is the **last** place the chosen disk
is printed.

Test only on a **disposable QEMU disk**:

```bash
qemu-img create -f qcow2 /tmp/ar0x-target.qcow2 40G
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -drive file=/tmp/ar0x-target.qcow2,format=qcow2,if=virtio \
  -cdrom out/ar0x-0.1.0-x86_64.iso -boot d        # Phase 11
```

## 3. Wizard step-by-step (the real Calamares 3.4 sequence)

`PROJECT_PLAN.md §8.3` gives a logical order. **ADR-026** maps it to the real
3-phase `show / exec / show` contract (a job module cannot be a GUI page, and
`bootloader` must write to an already-unpacked target):

| # | Phase | Module | What the user sees / what happens |
|---|---|---|---|
| 1 | show | `welcome` | ar0x logo, `0.1.0 (ar0x root)`, no internet requirement |
| 2 | show | `locale` | timezone + system locale |
| 3 | show | `keyboard` | layout/variant — **3.4.3 Wayland QML keyboard fix** (RISK-003) |
| 4 | show | `partition` | ⚠️ **RISK-004**: Erase / Manual, `initialPartitioningChoice: none`, ext4 default, btrfs offered, opt-in LUKS, 512 MiB ESP |
| 5 | show | `users` | real username + password (min 8), zsh, `wheel`, **no autologin**, root password |
| 6 | show | `packagechooser@ar0x-packages` | `minimal / standard / full` — official `[core]/[extra]` only |
| 7 | show | `summary` | last chance to read the **target disk name** |
| — | exec | `partition → mount → unpackfs` | squashfs → target |
| — | exec | `packages` | applies the chosen group; **offline**, `update_db/system: false` |
| — | exec | `machineid → fstab → locale → keyboard → localecfg` | target identity |
| — | exec | `shellprocess@ar0x-prep` | removes archiso initramfs drop-in + build-stamp hook |
| — | exec | `initcpiocfg → initcpio` | **Arch-native "initramfs" step** (`mkinitcpio`, ADR-026) |
| — | exec | `removeuser → users` | deletes the empty-password live `ar0x`, creates the real user |
| — | exec | `displaymanager → networkcfg → hwclock → services-systemd` | SDDM, NetworkManager, nftables |
| — | exec | `grubcfg → bootloader` | GRUB UEFI + BIOS, Secure Boot **off** (RISK-007 manual) |
| — | exec | `shellprocess@ar0x-finish` | first-boot sentinel + unit symlink + RISK-013 guard |
| — | exec | `umount` | `emergency: true`, so the target is never left mounted |
| 8 | show | `finished` | reboot button (`systemctl reboot`) |

Instances in `settings.conf`:

```yaml
instances:
- id: ar0x-packages   module: packagechooser  config: ar0x-packages.conf
- id: ar0x-prep       module: shellprocess    config: shellprocess-prep.conf
- id: ar0x-finish     module: shellprocess    config: shellprocess-finish.conf
```

`UPSTREAM_DEFAULT_MODULES` (`mount`, `fstab`, `localecfg`, `networkcfg`,
`hwclock`) intentionally have no local `.conf`; Calamares ships their defaults.

## 4. First-boot chain (what `ar0x-installer-finish` really does)

It runs **inside the target chroot** (last job before `umount`) with
`dontChroot: false`:

1. Writes the literal sentinel `uninitialized` to `/etc/machine-id`. The
   `machineid` job earlier writes a real id, but systemd's
   `ConditionFirstBoot=yes` needs this sentinel; systemd replaces it with a
   fresh id at first boot.
2. Creates a **plain symlink**
   `/etc/systemd/system/multi-user.target.wants/ar0x-firstboot.service` →
   `/usr/lib/systemd/system/ar0x-firstboot.service`. No `systemctl`/D-Bus is
   available in a chroot, so a symlink is the offline-safe equivalent of
   `systemctl --root=... enable`.
3. **RISK-013 guard:** removes the live-only sudoers drop-ins and **aborts the
   install** if any `NOPASSWD` rule remains (`ar0x-firstboot` asserts this
   again on the first boot).
4. Removes live-only state: `ar0x-live` sysusers drop-in, SDDM/getty autologin
   drop-ins, archiso mkinitcpio drop-in.
5. Writes `/var/lib/ar0x/installer-finished` for idempotency and post-mortems.

Then, on the installed system's first boot:

```
systemd → ar0x-firstboot.service (SYSTEM, ConditionFirstBoot=yes, ROOT, oneshot)
   └─> /usr/lib/ar0x/ar0x-firstboot   [from ar0x-welcome, signed [ar0x], Phase 11]
         ├─ RISK-013 guard: FAIL if any NOPASSWD rule survived
         ├─ enable the ar0x-welcome USER unit for all users
         └─ stamp /var/lib/ar0x/firstboot-done
       → ar0x-welcome (GTK4) appears on the first graphical login
```

⚠️ `ar0x-firstboot.service` is **deliberately NOT** in
`config/system/systemd/system-preset/50-ar0x.preset` — that preset is the
single owner of **live-ISO** service state, and the unit does not exist on the
ISO until Phase 11 installs `ar0x-meta`.

## 5. Configuration tradeoffs (ADR-026)

| Decision | Alternative rejected | Why |
|---|---|---|
| 3-phase `show/exec/show` | one flat module list | Calamares 3.4 requires view modules in `show` and job modules in `exec` |
| `packagechooser@ar0x-packages` + `packages` job | `netinstall` | `netinstall` needs network; v0.1 installs offline from squashfs |
| `initcpiocfg` + `initcpio` | `initramfs`/`initramfscfg` | Arch uses `mkinitcpio`; the Debian-style modules would rebuild nothing |
| `bootloader` after `unpackfs` | plan's literal "bootloader before unpackfs" | GRUB must write into an existing target rootfs |
| `/etc/calamares/branding/ar0x/` | `/usr/share/calamares/branding/ar0x/` | one owner per path; `/etc` takes precedence and needs no second sync target |
| `initialPartitioningChoice: none` + `prompt-install: true` | auto-erase | ⚠️ RISK-004, irreversible data loss |
| `update_db: false`, `update_system: false` | `pacman -Syu` during install | bare `-Sy` is forbidden by the §9 security contract; offline ISO |
| 3 package groups, official-only | AUR / `*-git` / `*-bin` | RISK-010 snapshot drift; `ar0x_installer.py` fails the build |
| `pkexec calamares` launcher | bare-root `sudo calamares` | polkit elevation, no blanket `NOPASSWD` (RISK-013) |
| `secureBoot: false` | auto MOK enrollment | RISK-007: enrollment is a manual firmware decision |
| `slideshowAPI: 2` pure-QML slideshow | image slideshow with extra PNGs | no extra binary art; 8 palette pins asserted by the validator |

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `Bad unpackfs configuration` | `sourcefs` must be exactly `squashfs`; never `directory` |
| `chroot: missing operand` | `shellprocess` has **no** `args:`/`arguments:` key; put the whole command in `script:` |
| `Skipping non-emergency job Unmounting file systems` | `umount.conf` needs `emergency: true` |
| `ar0x-firstboot.service` never runs | `/etc/machine-id` must be `uninitialized` on the target; `ar0x-installer-finish` writes it |
| `pacman: conflicting files` on `ar0x-meta` | ADR-024: packages must not own airootfs paths; `ar0x_pkgbuild.py` catches it |
| Keyboard dead in the QML page | You built the archived GitHub `v3.3.14`; use Codeberg `v3.4.3` (RISK-003) |
| Installer hangs at exec | `shellprocess` default timeout is 30 s; both ar0x instances set `timeout` |
| `error: target is busy` at reboot | `umount.conf` `emergency: true` missing |
| Wrong disk erased | ⚠️ **RISK-004 — irreversible.** Always `lsblk` first; no automated fix |
